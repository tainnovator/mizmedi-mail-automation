업무 메일 자동화, 실제로 만들어본 기록

매일 아침, 메일함부터 열어야 했던 시간을 돌려받았습니다

미즈메디병원 행정원장이 직접 문제를 겪고, AI와 대화하며 직접 만든 업무 메일 자동화 이야기입니다. 개발 경험 없이도, 한 단계씩 확인하며 끝까지 완성했습니다.

이전

받은편지함에 업무 메일과 광고성 메일이 뒤섞여 쌓입니다. 급한 메일을 놓치지 않았는지, 매번 하나씩 열어봐야 마음이 놓였습니다.

이후

매일 아침 8시, 카카오톡 메시지 한 통에 분류된 요약과 회신 초안까지 도착합니다. 훑어보는 데 1분이면 충분합니다.

왜 시작했는가

병원 메일함에는 매일 병원협회 소식, 거래처 안내, 광고성 메일, 그리고 정말 놓치면 안 되는 업무 메일이 뒤섞여 도착합니다. 하나씩 열어서 확인하는 시간도 아까웠지만, 더 큰 문제는 "혹시 중요한 걸 놓치지 않았을까" 하는 불안이었습니다. 반복되는 이 확인 작업을, 사람 대신 AI가 매일 아침 먼저 정리해두면 어떨까 하는 생각에서 시작했습니다.

열한 걸음의 여정

완벽한 설계도를 그리고 시작하지 않았습니다. 한 단계를 만들고, 실제로 돌려보고, 확인이 되면 다음 단계로 넘어가는 방식으로 진행했습니다.

1

메일함 여는 길 찾기

병원 메일 시스템에 있는 "자동전달" 기능을 발견하고, 자동화 전용으로 새로 만든 구글 계정으로 메일이 흘러오도록 연결했습니다.

2

첫 관문, 인증 통과하기

구글 계정 접근 권한을 안전하게 받아오는 절차를 거쳤습니다. 이 과정에서 병원 전체 메일 시스템에 영향을 줄 뻔한 설정을 발견해, 한 번 멈추고 담당자와 확인한 뒤 더 안전한 방법을 찾았습니다.

3

메일 분류 로직 만들기

정해진 규칙과 AI 판단을 함께 사용해서, 새로 온 메일을 업무·광고성·스팸·기타로 자동으로 나누게 했습니다.

4

요약과 회신 초안 준비

그날의 메일을 정리한 문서를 자동으로 만들고, 회신이 필요해 보이는 메일은 초안까지 미리 준비하게 했습니다. 실제 전송은 언제나 사람이 직접 합니다.

5

카카오톡으로 연결하기

문서를 열어봐야만 알 수 있던 결과를, 카카오톡 "나에게 보내기"로 짧게 요약해 받아볼 수 있게 만들었습니다.

6

하나의 흐름으로 잇기

메일 확인부터 카카오톡 알림까지, 따로 만들어둔 기능들을 하나로 이어서 처음부터 끝까지 자동으로 돌아가게 했습니다.

7

매일 아침 스스로 실행되게

컴퓨터가 매일 정해진 시간에 이 흐름을 스스로 실행하도록 예약해뒀습니다.

8

조금 더 똑똑하게 다듬기

업무 메일마다 1~2줄 핵심 요약을 알림에 함께 담아, 굳이 문서를 열지 않아도 내용을 바로 파악할 수 있도록 고도화했습니다.

9

초안까지 대신 써두게 하기

읽기 권한만으로는 확인까지만 가능했는데, 여러 겹의 안전장치를 마련한 뒤 쓰기 권한까지 확장해서 회신이 필요한 메일은 임시보관함에 초안까지 미리 준비해두도록 했습니다. 물론 전송 버튼은 여전히 사람만 누릅니다.

10

확인은 자주, 알림은 드물게

매시간 조용히 메일을 확인해 초안까지 준비해두고, 카카오톡 알림은 하루 세 번만 모아서 보내도록 역할을 나눴습니다. 알림이 너무 잦으면 오히려 안 보게 될 것 같다는 걱정과, 실시간으로 놓치고 싶지 않은 마음, 둘 다를 챙긴 결정이었습니다.

11

쌓여만 가던 첨부파일도 자동으로

매달 업체에서 오는 거래명세표 같은 첨부파일은 그동안 하나하나 열어서 직접 다운로드하고, 어느 폴더에 넣을지도 매번 손으로 정리했습니다. 발신자와 제목을 함께 확인해서 확실히 맞는 것만 골라 자동으로 다운로드하고, 업체별 폴더에 이름까지 붙여 정리해두도록 만들었습니다.

만들면서 겪은 일들

순탄하지만은 않았습니다. 몇 가지는 재미있었고, 한 번은 정말 아찔했습니다.

두 메일 시스템의 정리 방식이 서로 달랐습니다
사내에서 쓰는 아마란스10은 메일이 온 순서대로 쌓이고, 필요하면 폴더를 만들어 따로 분류할 수 있는 방식이었습니다. 반면 자동전달을 받는 Gmail 쪽은 "스레드" 방식이라, 한 메일에 대한 답장들이 같은 묶음 안에 모여서 오히려 관리가 더 편했습니다. 다만 폴더는 없고, 대신 "라벨"을 붙여서 분류하는 구조였습니다. 당연하게 여겼던 개념부터 하나씩 다시 확인해야 했습니다.
병원 전체 메일 시스템을 건드릴 뻔한 순간
설정 화면 하나가 병원 전체 임직원 계정에 영향을 줄 수도 있는 상황이었습니다. 확실하지 않으면 진행하지 않는다는 원칙에 따라 그 자리에서 멈추고 확인한 뒤, 더 안전한 다른 방법을 선택했습니다.
존댓말을 알려줬더니 갑자기 "사장님"이라 부르기 시작한 AI
사소한 해프닝도 있었습니다. "그렇게 부르지 말아달라"고 한 번 더 알려주니 바로 고쳐졌습니다.
처음 보는 에러 코드와의 씨름
낯선 에러 코드가 뜰 때마다 당황스러웠지만, 대부분은 설정 화면에서 항목 하나를 빠뜨렸거나 순서를 건너뛴 게 원인이었습니다. 하나씩 원인을 좁혀가며 해결했습니다.
알림이 너무 잦아도, 너무 뜸해도 문제였습니다
메일이 올 때마다 알림이 오면 결국 안 보게 될 것 같았고, 그렇다고 하루 한 번만 확인하면 낮 시간에 놓치는 메일이 생겼습니다. "확인은 매시간 조용히, 알림은 하루 세 번만 모아서"로 역할을 나누고 나서야 두 걱정이 동시에 풀렸습니다.
이미 제가 직접 답장한 메일까지 또 초안을 만들 뻔했습니다
정해진 시간에 자동으로 확인하기 전에 제가 먼저 직접 답장을 보낸 적이 있었는데, 자동화가 이걸 모르고 또 초안을 만들려던 걸 발견했습니다. 초안을 만들기 전에 "혹시 이미 내가 답장한 메일인가"부터 먼저 확인하도록 안전장치를 하나 더 추가했습니다.
놀랄 필요 없는 일에 놀랄 뻔했습니다
자동화가 쓰는 계정 표시가 평소 보던 주소와 살짝 달라서 순간 "계정이 잘못됐나" 걱정했습니다. 확인해보니 이미 알고 있던 정상적인 메일 시스템 구조(같은 메일함의 별칭 주소)였을 뿐, 실제로는 아무 문제가 없었습니다. 걱정이 될 때 바로 고치기보다 먼저 확인하는 습관이 도움이 됐습니다.
같은 사람이 보낸 다른 메일까지 다운로드될 뻔했습니다
발신자 주소 하나만 보고 판단하면, 같은 사람이 보낸 전혀 다른 메일(예: 계약서)까지 자동으로 다운로드될 위험이 있었습니다. 발신자와 제목의 키워드를 모두 확인했을 때만 다운로드하도록 만들고, 하나만 맞는 경우는 따로 표시만 해두어 사람이 나중에 직접 확인하도록 했습니다.
미리보기부터 해보는 습관이 붙었습니다
새 기능을 만들 때마다, 실제로 실행하기 전에 "이렇게 될 예정입니다"만 먼저 보여주는 모드를 만들어서 확인한 뒤에 진짜로 실행하는 순서가 점점 당연한 습관이 되었습니다.

느낀 점

비개발자도 만들 수 있습니다

코드를 몰라도, 무엇이 필요한지 정확히 설명하고 AI와 함께 한 단계씩 확인하며 나아가면 실제로 동작하는 시스템을 완성할 수 있었습니다.

작게 나누는 게 결국 더 빨랐습니다

한 번에 다 만들려 하지 않고, 한 단계씩 확인한 뒤 다음으로 넘어간 덕분에 문제가 생겨도 원인을 바로 찾을 수 있었습니다.

사람의 마지막 확인은 타협하지 않았습니다

자동화가 하는 일은 정리와 초안까지이고, 확인과 전송, 승인은 항상 사람의 몫으로 남겨뒀습니다. 그래야 안심하고 계속 쓸 수 있었습니다.

권한의 이름만 보고 안심하지 않았습니다

"초안 작성" 권한 하나에도 생각보다 넓은 기능(예: 발송까지 포함)이 딸려 올 수 있다는 걸 알게 됐습니다. 권한 이름만 믿지 않고 실제로 무엇이 가능한지 확인한 뒤, 코드 안에서 한 번 더 막아두는 이중 안전장치를 뒀습니다.

완벽한 계획보다 실제로 돌려보는 게 빨랐습니다

처음 세운 계획대로 되지 않은 부분이 많았지만, 그때그때 확인하며 방향을 바꿔서 결국 원하는 결과에 도달했습니다.

반복되는 손이 가는 일부터 하나씩 걷어냈습니다

메일 확인, 회신 초안, 이제 첨부파일 정리까지 — 자동화를 하나씩 더할 때마다 어떤 반복 작업이 실제로 시간을 잡아먹는지 다시 보게 됐습니다. 한 번에 다 하려 하지 않고, 눈에 밟히는 불편함부터 하나씩 자동화해나가는 방식이 가장 오래갔습니다.

완성은 끝이 아니라 시작이었습니다

처음부터 완벽하게 만들 수는 없습니다. 기초 골격을 세우고 실제로 돌려본 뒤, 쓰면서 발견되는 불편함을 계속 다듬어가는 과정 자체가 자동화의 일부였습니다.

반복되는 업무는 대부분 같은 네 단계로 만들 수 있습니다

메일 자동화든, 세금계산서 정리든, 그 밖에 매번 손으로 반복하는 업무든 — 아래 네 단계 틀에 대입해보면 어디서부터 시작할지 감이 잡힙니다.

자동화의 네 단계

1

자료 확보

처리하고 싶은 정보가 어디서 오는지 찾고, 자동으로 전달받을 통로를 만듭니다.

2

접근 권한

그 정보에 프로그램이 안전하게 접근하도록 권한을 받아옵니다.

3

처리 로직

규칙이나 AI 판단으로 필요한 것을 골라내고 정리·가공합니다.

4

결과 전달

보기 편한 방식으로 결과를 전달하고, 정해진 시간에 자동 반복되게 합니다.

메일 자동화는 이렇게 대입했습니다

단계실제로 한 일
1병원 메일함의 자동전달 기능으로, 자동화 전용 구글 계정에 메일을 확보
2구글·카카오 로그인 인증으로 프로그램이 대신 접근할 권한을 확보
3규칙과 AI를 함께 사용해 업무·광고성·스팸으로 분류하고, 요약과 회신 초안을 생성
4카카오톡 알림으로 전달하고, 매일 아침 자동 실행되도록 예약

다른 업무에 적용한다면

예를 들어 "세금계산서·첨부파일 자동 정리"도 같은 틀로 설명할 수 있습니다.

단계세금계산서 자동화라면
1국세청·거래처에서 오는 메일을 지정 계정으로 자동전달
2같은 방식으로 메일 접근 권한을 확보
3첨부파일 중 세금계산서로 보이는 것만 가려내기
4지정 폴더에 자동 저장하고 "새 세금계산서 N건 도착" 알림 전송
· 승인이나 확정처럼 회계·행정상 최종 결정이 필요한 절차는 자동화하지 않습니다. 자동화는 자료를 모으고 정리하는 데까지이고, 확인과 승인은 항상 담당자가 직접 합니다.

실제로는 발신자와 제목을 함께 확인해서 이런 식으로 판정하고 저장합니다. (예시 값입니다)

발신자: vendor@example.com | 제목: A업체 9월 거래명세표 발송 | 결과: 다운로드 발신자: vendor@example.com | 제목: Fwd: 전자계약서 | 결과: 미확인 (발신자만 일치) 저장된 파일: A업체_202609_거래명세표.pdf

직접 따라 하는 설치 가이드

이 자동화는 "Claude Code"라는 도구로 만들었습니다. VS Code라는 프로그램 안에서 원하는 것을 대화하듯 설명하면, AI가 실제로 동작하는 코드를 대신 만들어 줍니다. 개발 경험이 없어도 시작할 수 있고, 아래는 실제로 거쳤던 순서 그대로입니다. 화면 속 값은 전부 예시이며, 실제 발급받는 값은 본인만 볼 수 있는 곳에 보관하세요.

0

준비물

  • VS Code 설치
  • VS Code에 Claude Code 확장 설치
  • 자동화 전용으로 쓸 이메일 계정 하나 정해두기 (기존 개인 계정과 섞이지 않도록)
1

메일 확보 경로 만들기 — 사내 메일 시스템

  • 메일 > 환경설정 > 메일 자동전달 메뉴로 이동
  • 메일 주소 목록에 자동화 전용 이메일 계정 추가
  • 포워딩 사용여부를 '예'로 설정하고 저장

발신(답장 보내기)은 이 설정과 무관하게 별도로 이루어집니다. 이 단계는 "수신"만 연결합니다.

2

Google Cloud에서 접근 권한 만들기

  • console.cloud.google.com 접속 후 새 프로젝트 생성
  • API 및 서비스 > 라이브러리에서 "Gmail API" 검색 후 사용 설정
  • OAuth 동의 화면에서 앱 이름 입력 (대상은 조직 내부용이면 '내부', 아니면 '외부')
  • 사용자 인증 정보 > OAuth 클라이언트 ID 만들기, 유형은 '데스크톱 앱' 선택
  • 생성된 JSON 파일을 다운로드해 프로젝트 폴더 안 credentials 폴더에 보관
client_id: 1234567890-abcdefghijklmno.apps.googleusercontent.com
예시입니다. 실제 값은 credentials 폴더 안에만 두고 누구와도 공유하지 마세요.
3

카카오톡 알림 받을 준비

  • developers.kakao.com에서 새 애플리케이션 생성
  • [앱] > [플랫폼 키]에서 REST API 키 확인
  • [카카오 로그인]을 활성화(ON)
  • 같은 화면에서 '카카오 로그인 리다이렉트 URI' 등록 (예: http://localhost:8888/callback)
  • [동의항목]에서 '카카오톡 메시지 전송'을 선택 동의로 설정 후 저장
  • 필요 시 클라이언트 시크릿 코드도 함께 확인해 보관
REST API 키: a26cf7ddd3f5de900977ee5e8eb9dfc7
예시입니다. 이 값도 credentials와 동일하게 보호해야 합니다.
4

Claude Code에게 자동화 요청하기

  • 새 프로젝트 폴더를 만들고 VS Code로 열기
  • Claude Code 패널에 목표와 원칙, 오늘 진행할 범위를 정리해서 요청
예시 요청: "OO 업무 자동화를 시작하려고 해. [목표] 무엇을 자동으로 처리하고 싶은지 [원칙] 최종 확인·전송·승인은 항상 사람이 한다. 비밀번호·키는 코드에 직접 적지 않고 .env에서 읽어온다. [오늘 범위] 프로젝트 폴더 구조와 CLAUDE.md, .env.example 파일만 먼저 만들어줘."

이렇게 요청하면 CLAUDE.md, .env.example, 폴더 구조가 자동으로 만들어집니다. 한 번에 다 시키지 말고, 오늘 할 범위를 매번 정해서 요청하는 게 핵심입니다.

이렇게 단계를 밟아 나가면, 회신 초안은 결국 Gmail 임시보관함에 이런 모습으로 쌓입니다. (예시 값입니다)

✉️ Gmail 임시보관함 · 초안
Re: [예시] 회의 일정 조율 부탁드립니다
받는사람: example@partner.com
5

인증 정보 채워 넣기

  • .env.example을 복사해 .env 파일 생성
  • 앞서 2·3단계에서 확인한 값들을 각 항목에 채워 넣기
  • Google에서 받은 JSON 파일은 credentials 폴더 안에 그대로 보관
  • .env와 credentials 폴더는 절대 남에게 공유하거나 깃허브에 올리지 않기
6

실제로 실행해서 확인하기

  • Claude Code가 만들어준 테스트 스크립트를 터미널에서 실행
  • 처음 실행 시 뜨는 브라우저 로그인 창에서 자동화 전용 계정으로 로그인 후 권한 허용
  • 카카오톡 "나와의 채팅방"에 실제로 메시지가 도착하는지 확인

로그인이 정상적으로 끝나면 터미널에 이런 확인 메시지가 뜹니다. (예시 값입니다)

인증 성공: example@yourcompany.com 요청 스코프: gmail.readonly, gmail.compose
7

매일 자동으로 실행되도록 예약

  • 사용 중인 컴퓨터가 macOS면 launchd, Windows면 작업 스케줄러를 사용
  • Claude Code에게 "매일 오전 O시에 이 스크립트를 자동 실행하도록 등록해줘"라고 요청
  • 안내받은 등록 명령어를 순서대로 하나씩 터미널에 입력하며 확인

컴퓨터가 그 시간에 꺼져 있거나 잠자기 상태였다면, 다음에 켤 때 한 번 실행되며 놓친 것 없이 이어집니다.

반드시 지키는 세 가지 원칙

1

최종 확인과 전송, 승인은 항상 사람이 합니다. AI는 정리와 초안까지만 만듭니다.

2

비밀번호와 접근 키는 코드에 직접 적지 않습니다. 안전한 곳에 따로 보관하고, 필요한 곳에서만 불러와 씁니다.

3

한 번에 다 만들려 하지 않습니다. 한 단계씩 만들고, 실제로 확인한 뒤 다음 단계로 넘어갑니다.

이 페이지는 미즈메디병원 행정원장에서 실제 업무 자동화 경험을 바탕으로 작성했습니다.
